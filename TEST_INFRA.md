## 1. Testing Methodology & Architecture

The E2E test suite in `tests/run_e2e.js` is a **zero-dependency Node.js opaque-box test runner** that evaluates the application from the user and specification perspective (`ORIGINAL_REQUEST.md` and `PROJECT.md § Feature Inventory` & `§ Interface Contracts`):
1. **Sandboxed Browser VM & DOM Harness**: Parses `public/index.html` and executes all client scripts (`js/artAssets.js`, `js/avatarCanvas.js`, `js/combatCanvas.js`, `js/huntingCanvas.js`, `js/views/mainViews.js`, `js/views/specialModals.js`, `js/views/chatPanel.js`, `js/uiShell.js`, `js/app.js`) inside an isolated `vm` context with simulated `localStorage`, HTML5 2D `<canvas>` context operation capture, `requestAnimationFrame` queue inspection, WebAudio synthesizer stubs, and interactive DOM querying/dispatching.
2. **HTTP Server & Static Mirror Verification**: Boots `server/index.js` on an ephemeral port to test `/api/health`, HTML/CSS/JS/image asset serving, path traversal protection (`403`/`404`), and byte-for-byte mirror synchronization between `public/` and the repository root (`index.html`, `css/asteria.css`, `js/**`, `assets/**`) for GitHub Pages deployment.
